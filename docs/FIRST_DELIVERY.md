# FIRST DELIVERY — Phase 16 PRIMARY 001

## Overview

PRIMARY 001 FIRST DELIVERY is the canonical prologue mission that seeds the unstable
five-faction sandbox. It is implemented via the generic MissionSystem (Phase 15),
not bespoke world hacks. After delivery completes, a procedural rival discovers the
fictional drug, triggering the structural four-year strategic history transition.

## Canonical identity

- **Template ID**: `"PRIMARY_001_FIRST_DELIVERY"` (Phase 16 constant
  `primaryFirstDeliveryTemplateId = 1`, template string `"PRIMARY_001_FIRST_DELIVERY"`
  in `prologue_system.cpp:38`)
- **Category**: `MissionCategory::Primary`
- **Title**: `"First Delivery"`
- **Giver**: `NpcId` of the origin faction's leader (not EntityId)
- **Recipient**: `NpcId` of a major NPC from the origin faction (non-leader, alive)
- **Payload**: `fictionalProductToken = 1` (abstract, non-instructional)

## Objective graph

```
START (GO_TO) → INTERACT → DELIVER → COMPLETE MISSION
```

| Step | Type | Target | Condition | Transition |
|------|------|--------|-----------|------------|
| 1 | GO_TO | Faction leader | LocationReached | Activate INTERACT |
| 2 | INTERACT | Faction leader | InteractionOccurred | Activate DELIVER |
| 3 | DELIVER | Recipient NPC | ItemDelivered | CompleteMission |

All three objectives must complete for the mission to reach `MissionState::Completed`.
The `COMPLETE` terminal transition is on the DELIVER objective's `OnSuccess` trigger.

## Wrong completion does not work

- Wrong payload (`payloadItemId != fictionalProductToken`): `notifyDeliveryCompleted`
  at `mission_system.cpp:464` checks `objDef.payloadItemId == payloadItemId` before
  marking the objective complete.
- Wrong recipient: same check — `objDef.recipientNpc == recipient` required.
- Wrong destination: `notifyLocationReached` checks the objective ID matches; the
  location is bound to the faction leader's position in the objective definition.

## Rival discovery

The discovery incident is generated by `historyPrologueCandidate()` in
`history_system.cpp:146`, which:
1. Collects all factions except the origin as candidate rivals.
2. Derives a deterministic RNG from `seed → "history.discovery.v1" → origin faction`.
3. Selects one rival via uniform draw.
4. Picks a random witness (NPC belonging to the rival faction).
5. Selects one of 6 `DiscoveryIncident` categories:
   - RivalWitness (0)
   - Betrayal (1)
   - AccidentalExposure (2)
   - PoliceInterference (3)
   - WrongDestination (4)
   - InformationLeak (5)

Selection inputs: `state.metadata.seed`, `"history.discovery.v1"` domain tag,
`origin` FactionId. No runtime RNG is consumed.

## History gating

- `runPrologue` (prologue_system.cpp:137) requires `!state.history.version` — no
  existing history before prologue begins.
- `beginStrategicHistory` (history_system.cpp:156) validates evidence via
  `checkEvidence`, which requires `firstDeliveryCompleted == true` and
  `deliveryTick <= discoveryTick`.
- `validatePrologueState` (prologue_system.cpp:205) requires `history.version != 0`
  for phase >= DeliveryComplete.
- After history starts, `Game::tick` (game.cpp:112) blocks runtime simulation until
  `history.months == historyMonths` (48).

## Four-year transition

- `historyMonths = 48`, `historyDays = 1460`, `gameDayTicks = 38400`.
- Each `advanceStrategicHistory` call advances one month:
  `end = startTick + month * 1460 / 48 * 38400`.
- Full transition: 48 calls, ending at `startTick + 56,064,000` ticks.
- Markets update daily, dealers expand, territories settle, relationships form,
  politics rotate. No physical entities are created or destroyed.

## "4 YEARS LATER" semantic state

The structural transition is represented in persistent state, not text rendering:
- `StrategicHistory.version == 1`
- `StrategicHistory.months == 48`
- `StrategicHistory.events[0].kind == FirstDelivery` (origin faction)
- `StrategicHistory.events[1].kind == RivalDiscovery` (rival faction, witness NPC, location)
- `StrategicHistory.informed.size() == 5` (all factions entered the market)
- `PrologueState.phase == Complete`

## Post-history StoryGraph

After `advanceStrategicHistory` completes month 48:
1. `initializeStoryGraph(state)` (story_system.cpp:103) projects opportunities.
2. Standard five-faction graph: **70 nodes, 60 dependency edges, 5 eligible**.
3. StoryGraphVersion = 1.
4. `validatePostTimeskipWorld` confirms:
   - All 5 factions viable (treasury > 0, reserveMembers >= 4, living leader)
   - Markets city-wide (demand > 0, supply > 0, price < max)
   - Unresolved tension exists (hostility >= 4500 with grievance)
